# werewolf dev 브랜치 게임 규칙 검증

검증일: 2026-10-20, 한국 시간  
대상: https://github.com/KJM0603/werewolf  
브랜치: `dev`  
커밋: `6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a`  
환경: Windows, Node.js v24.19.0

**판정: 기본적인 한 판 진행은 가능하지만, 모든 규칙이 정상 작동하는 상태는 아닙니다. 승패와 비밀 정보에 영향을 주는 수정이 필요합니다.**

저장소의 `DESIGN.md`를 주된 기준으로 삼았고, 원작과 차이가 있는 부분은 별도로 구분했습니다. 검증용 파일만 이 outputs 폴더에 만들었으며, 내려받은 저장소의 게임 코드는 수정하지 않았습니다. 커밋과 푸시도 하지 않았습니다.

## 우선 수정이 필요한 문제

### 1. [P1] 재접속하면 몰래 바뀐 현재 역할을 알 수 있습니다

- 재현: 주정뱅이가 중앙의 무두장이 카드와 교환한 뒤 재접속합니다.
- 기대: 주정뱅이는 새 카드를 볼 수 없으므로, 이미 알던 정보만 복원되어야 합니다.
- 실제: 서버가 `role:private`로 `tanner`를 전송합니다.
- 영향: 주정뱅이뿐 아니라 말썽쟁이 등으로 카드가 바뀐 참가자도 새로고침으로 최종 역할을 알아낼 수 있습니다. 추리의 핵심인 비밀 교환이 무너집니다.
- 원인: 재접속에서 참가자가 마지막으로 확인한 역할 대신 `roleForPlayer()`의 현재 역할을 전송합니다.
- 위치: [server.mjs 474–476행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L474-L476)
- 재현 테스트: `BUG-1`
- 수정 방향: 실제 카드 상태와 참가자에게 허용된 지식 상태를 따로 저장하고, 재접속 시 후자만 복원합니다.

### 2. [P1] 도플갱어의 카드가 바뀌면 개인 승패가 잘못 판정됩니다

- 재현 A: 도플갱어가 강도를 복사하고 늑대인간 카드를 훔칩니다. 최종 늑대가 살아남아 늑대 팀은 승리하지만 해당 참가자는 패배합니다.
- 재현 B: 도플갱어가 늑대를 복사한 뒤 말썽쟁이가 그 카드와 주민 카드를 교환합니다. 최종 주민이 된 참가자는 마을 팀이 이겨도 패배합니다.
- 기대: 게임 종료 시 실제로 소유한 카드에 따라 승패를 계산해야 합니다.
- 원인: 최종 역할을 기준으로 정상 계산한 `winners`를 다시 순회하며, 시작 역할이 도플갱어였던 사람의 승패를 최초 복사 역할로 덮어씁니다.
- 위치: [server.mjs 385–392행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L385-L392)
- 재현 테스트: `BUG-2`, `BUG-3`
- 수정 방향: 복사 정보는 도플갱어 카드에 귀속시키되, 개인의 승패는 마지막에 가진 카드로 일관되게 계산합니다.

### 3. [P1] 밤 행동 도중 일시정지하면 재개 후 행동 UI가 사라집니다

- 재현: 예언자의 선택 화면이 떠 있는 동안 방장이 일시정지한 후 재개합니다.
- 기대: 남은 시간과 대상 선택 화면이 복원되어야 합니다.
- 실제: 클라이언트는 `paused` 상태를 받으면 `state.prompt`를 지웁니다. 재개 시 서버가 `night:prompt`를 다시 보내지 않아 선택 화면이 돌아오지 않습니다.
- 영향: 서버는 해당 참가자의 행동을 기다리는데 참가자는 화면에서 행동할 수 없으며, 시간이 지나면 미행동 처리됩니다.
- 위치: [public/app.js 32–41행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/public/app.js#L32-L41), `server.mjs`의 `game:resume` 처리
- 재현 테스트: `BUG-9`
- 수정 방향: 정지 중 프롬프트를 보관하거나, 재개 시 현재 행동자에게 선택 화면 정보를 다시 전송합니다. 일시정지 상태에서 접속한 참가자도 포함해야 합니다.

### 4. [P1] 밤 순서만 봐도 중앙에 들어간 역할을 추론할 수 있습니다

- 재현: 참가자 카드는 늑대·주민·주민, 중앙은 예언자·강도·말썽쟁이로 둡니다.
- 실제: 공개된 밤 순서에는 늑대만 등장하고 바로 토론으로 넘어갑니다. 선택된 카드 목록과 비교하면 나머지 세 역할이 중앙에 있다는 사실을 알 수 있습니다.
- 원인: `hasPendingActor()`가 실제 참가자에게 배정된 역할만 다음 단계로 선택하며, 현재 역할을 `nightTurn`으로 모두에게 공개합니다.
- 위치: [server.mjs 251–258행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L251-L258), [공개 상태 93행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L93)
- 재현 테스트: `BUG-7`
- 구분: 설계서의 “해당 역할이 없으면 자동으로 다음 단계”를 따르는 구현이지만, 같은 설계서의 비밀 정보 보호 목표와 충돌하는 **설계 수준 문제**입니다.
- 수정 방향: 선택된 덱에 있는 밤 역할은 중앙에 있더라도 같은 공개 순서로 진행하고, 행동 유무나 제출 속도가 배정을 드러내지 않도록 합니다.

### 5. [P2] 새로고침하면 이전에 확인한 밤 정보를 복원하지 못합니다

- 재현: 예언자가 중앙 카드 두 장을 확인한 후 재접속합니다.
- 기대: 이미 확인한 두 카드 정보가 유지되어야 합니다.
- 실제: 재접속 응답에는 이전 `night:result`가 없고, 브라우저의 `privateResults`도 초기화됩니다.
- 영향: 예언자의 확인 결과, 늑대·프리메이슨의 동료 정보 등 합법적으로 얻은 정보가 새로고침 후 사라집니다. 1번 문제와는 반대로 필요한 정보가 누락됩니다.
- 위치: [server.mjs 117–120행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L117-L120), [재접속 473–482행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L473-L482)
- 재현 테스트: `BUG-6`
- 수정 방향: 개인별 공개 허용 정보 이력을 서버에 보관하고 안전하게 복원합니다.

### 6. [P2] 예언자가 도플갱어를 보면 복사한 비밀 역할까지 알게 됩니다

- 재현: 도플갱어가 늑대를 복사한 뒤 예언자가 그 사람을 확인합니다.
- 실제: “도플갱어” 카드 대신 “늑대인간”이라고 알려 줍니다.
- 구분: 원작은 **카드 자체를 보는 능력**이므로 복사한 선택까지 자동으로 공개하지 않습니다. 디지털판에서 실제 소속 역할을 공개하려는 의도라면 명시적인 변형 규칙 안내가 필요합니다.
- 원인: 카드 표시용 역할과 승패 계산용 역할을 동일한 `roleForPlayer()`로 처리합니다. 강도의 새 카드 확인 등에도 같은 구분이 필요합니다.
- 위치: [server.mjs 337행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L337), [역할 계산 122–124행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L122-L124)
- 재현 테스트: `BUG-5`

### 7. [P2] 하수인을 복사한 도플갱어의 정보 확인 시점이 다릅니다

- 기대: 설계서에 따르면 도플갱어 단계에서 즉시 늑대를 확인해야 합니다.
- 실제: 복사 역할에 저장한 뒤 늑대 단계를 거쳐 일반 하수인 단계에서 정보를 줍니다.
- 영향: 밤 순서가 명세와 다릅니다. 현재 기본판에서는 최종적으로 받는 늑대 목록이 대체로 같으므로 승패 오류보다 우선순위는 낮습니다.
- 위치: [server.mjs 128행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L128), [복사 후 분기 354–361행](https://github.com/KJM0603/werewolf/blob/6e8aae6c20ee3bd38b1106bee0e4ca89fe6b344a/server.mjs#L354-L361)
- 재현 테스트: `BUG-4`

## 통과한 주요 규칙

- 3~10인 카드 배분에서 참가자 수 + 3장, 중앙 3장, 중복 없는 카드 ID, 각 참가자 카드 한 장.
- 외톨이 늑대의 중앙 카드 한 장 확인 및 재조회 차단.
- 예언자 중앙 카드 두 장 확인, 중복 중앙 인덱스 차단, 다른 사람에게 확인 결과가 전송되지 않음.
- 강도 교환 및 새 역할 확인, 교환당한 참가자는 시작 역할에 맞춰 밤 행동.
- 말썽쟁이의 자기 자신 포함 교환 거부.
- 주정뱅이의 중앙 교환 및 새 역할 비공개.
- 불면증 환자의 바뀐 현재 카드 확인.
- 프리메이슨의 동료 확인과 하수인의 늑대 확인.
- 늑대 처치/생존, 늑대가 없고 사망자도 없는 경우, 무두장이 처치, 하수인의 무늑대 승리, 사냥꾼의 추가 처치, 늑대·무두장이 동점 처치.
- 투표 대상 비공개와 중복 투표 변경 거부.
- 방장 외 일시정지 거부, 일시정지 중 행동·투표 미적용.

## 실제 플레이 관찰과 한계

브라우저에서는 강도 역할을 받았습니다. 5초 선택 시간이 지나 수동 카드 교환은 수행하지 못했고, 밤 미행동 처리 뒤 토론으로 진행됐습니다. 채팅 전송과 1분 연장권의 1회 제한을 확인했고, 투표를 제출하여 결과 화면에 도달했습니다. 중앙에 늑대 2장이 있었고 마을 참가자가 처치되어 전원 패배한 결과는 해당 배치의 규칙에 맞았습니다.

7인 네트워크 검증에서는 실제 서버를 수정하지 않고 사용했습니다. 네트워크 참가자들은 받은 밤 프롬프트에 응답했으며, 연결 종료와 동일 토큰 재접속도 수행했습니다. 긴 토론을 끝낼 때만 저장소에 구현된 봇 테스트용 `game:skip-phase`를 사용했습니다. 브라우저 판도 토론 건너뛰기 버튼을 사용했습니다. 따라서 10분 토론 타이머를 끝까지 기다리는 검증은 하지 않았습니다.

다음 사항은 이번 검증만으로 정상이라고 단정할 수 없습니다.

- 실제 여러 사람·휴대전화·서로 다른 네트워크 사이의 음성/영상 연결.
- 마이크 권한 거절, TURN이 필요한 네트워크, 모바일 화면과 백그라운드 복귀.
- 모든 카드 조합, 모든 동률·다중 특수역할 조합의 완전 탐색.

설계서에는 시작/최종 역할, 행동 기록, 투표 결과 공개가 있으나 실제 결과 화면은 최종 역할·사망·승패 중심입니다. 서버 결과에는 시작 역할과 득표 수가 있지만 화면에서 표시하지 않으며, 개인별 투표 대상·전체 행동 이력도 제공되지 않습니다. 원인 확인을 위해 결과 화면 정보 확장을 권장합니다.

또한 주정뱅이의 시간 초과를 “교환하지 않음”으로 처리하는 것은 설계서에 명시된 MVP 정책입니다. 원작의 필수 교환과 차이는 있지만 이번 보고서에서 구현 오류로 집계하지 않았습니다.

## 재실행

이 보고서와 테스트는 현재 작업 폴더의 `outputs`에, 검증 대상 저장소는 `work/werewolf`에 있습니다. 현재 작업 폴더에서 실행합니다.

```powershell
node --test work/werewolf/tests/lone-wolf.test.mjs
node --test outputs/rules-audit.test.mjs
```

두 번째 명령은 발견된 문제를 정상 규칙에 대한 assertion으로 남겼으므로 현재 커밋에서는 **8개 실패가 예상됩니다**.

다른 체크아웃을 검증하려면:

```powershell
$env:WEREWOLF_REPO = '검증할 저장소의 절대 경로'
node --test outputs/rules-audit.test.mjs
```

네트워크 검증은 별도 터미널에서 서버를 먼저 실행한 후 진행합니다.

```powershell
Set-Location work/werewolf
$env:PORT = '4184'
node server.mjs
```

현재 작업 폴더의 다른 터미널:

```powershell
node outputs/live-protocol-audit.mjs
```
